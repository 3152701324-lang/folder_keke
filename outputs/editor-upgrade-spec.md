# 折纸地图编辑器升级规格

## 目标与范围

在现有 Three.js 2.5D 浮空纸张编辑器上，完善地图创作、机制验证与多关卡交付流程。保留俯视/固定视角、缩放拖拽、八向一步移动和镜像传送规则。传送交互保持：选择折纸线 → 预览目标 → 点击高亮目标传送。

本文件是升级计划，不代表下面所有功能已经实现。

## 1. 地图编辑

- 框选、复制、粘贴、移动、删除选区。
- 批量改色、连通区域填充、按住指针连续绘制。
- 水平/垂直对称绘制；选区旋转、水平翻转、垂直翻转。
- 坐标、网格与图层显示控制。
- 编辑撤销、重做、自动保存与保存失败反馈。

操作约定：框选基于地图坐标；粘贴与移动先预览，越界时拒绝整次操作；连续拖绘记为一次撤销操作。填充按四向连通、相同颜色分区，不穿越空格。对称绘制以地图中心为轴。

选区变换同时更新格内折纸方向。起点与出口属于独立标记图层：复制地形不复制唯一标记，移动/旋转/翻转选区内标记时同步变换玩家朝向；删除其承载方块后明确显示校验错误，禁止进入试玩。图层隐藏只改变显示，不改变游戏规则。

## 2. 折纸设计

- 放置、修改、移除横、竖、两种对角折纸线。
- 显示对称轴贯穿地图的完整线段与镜像配对格。
- 指定临时玩家测试站位，同时预览全部折纸落点。
- 标注非法原因：空格、阻挡、越界、位于轴上。

测试站位不修改正式起点。折纸采用轴所在格中心和轴方向定义的无限直线，显示时裁剪到地图边界。非法目标即使无法高亮实际格，也要显示坐标与原因。配对格显示可按单轴筛选，避免多轴叠加遮挡地图。

## 3. 关卡管理

- 创建、复制、删除、排序关卡。
- 设置名称、说明、起点、出口、最大步数、目标步数。
- 保存设计备注、具名版本快照与恢复快照。
- 用分类与排序组织教学关、练习关、挑战关。

每关有稳定 ID，复制关卡生成新 ID；下一关按关卡组排序决定。最后一关完成后显示整组完成。删除关卡可通过项目撤销恢复，保留至少一个可编辑关卡。版本快照保存关卡设计数据，恢复快照作为一次可撤销编辑。

## 4. 校验与求解

- 检查数据格式、地图尺寸、方块、折纸方向、起点与出口。
- 判断能否通关，计算最短解，并区分无步数限制可达与预算内可达。
- 回放解法、显示移动/折纸路线及每步落点。
- 计算仅普通移动的解，检查绕行；比较参考路线与最短解，提示潜在意外捷径。
- 逐条禁用折纸轴重新求解，判断能否跳过该轴，并报告替代解步数。
- 检测从起点不可达的可走格，以及可达但无法抵达出口的状态。

全部求解使用与试玩相同的合法动作和镜像规则。仅凭最短解不能判断作者意图，需参考路线或必需机制标记。机制依赖检查分别报告“任何步数能跳过”和“关卡预算内能跳过”。

当前规则下朝向不影响动作合法性和通关，坐标可作为搜索状态；解法回放仍恢复真实朝向。预算相关检查纳入已用步数。所有失败动作不扣步数，到达出口也必须满足最大步数，最大步数 0 表示无限制。

当前镜像和八向移动是可逆的，暂不存在不考虑预算时的单向陷阱；检测器应如实报告这一结果。分析异步运行，支持取消，并标记报告对应的地图版本；地图变更后旧报告失效。

## 5. 试玩与反馈

- 从正式起点或临时指定位置一键试玩。
- 退出试玩后恢复进入前的地图、编辑历史、选区与视角。
- 重启、撤销，通关后进入下一关。
- 分层提示：区域提示 → 机制提示 → 下一步。
- 记录试玩的移动/折纸动作、坐标、步数和结果，辅助关卡调整。

试玩不修改关卡设计。重启回到本次试玩的起始站位；指定站位试玩标为测试，不记录正式通关成绩。撤销恢复计数、朝向和胜负状态。下一步提示基于玩家当前状态求解，当前状态无预算内解时提示撤销或重启。提示通过玩家主动请求逐级展开。

## 6. 导入与导出

- 导入/导出单关卡 JSON，兼容当前 version 1 地图。
- 导入/导出完整关卡组，支持替换或追加并处理重复 ID。
- 导出包含所有依赖的单文件地图编辑器。
- 导出包含关卡组、提示和关卡推进的独立 game.html。

导入先完整解析和校验，失败不改动当前项目。项目格式有独立版本字段。独立游戏不显示编辑工具，也不包含私密设计备注、版本快照或试玩日志。HTML 内嵌数据安全转义，离线打开可运行，不依赖 CDN。

## 数据与模块边界

| 数据 | 归属与约定 |
| --- | --- |
| 关卡设计 | ID、分类、名称、说明、地图、起点、出口、maxSteps、targetSteps、提示、备注、参考路线 |
| 玩家成绩 | 最佳实玩步数与进度；独立保存，不能将当前 bestSteps 当作作者目标步数 |
| 项目数据 | 关卡顺序、当前关卡 ID、版本快照 |
| 编辑状态 | 工具、选区、剪贴板、图层、撤销/重做历史 |
| 运行状态 | 玩家、朝向、步数、动作历史、通关/失败状态 |
| 分析报告 | 地图版本、可达性、最短解、机制依赖、参考路线差异 |

游戏规则模块供预览、试玩、求解和回放共用；Three.js 负责显示与拾取，不能独立实现另一套规则。自动保存保留设计与进度的边界，存储失败必须提示，不默默宣称已保存。

## 实施顺序与验收

| 阶段 | 核心内容 | 可执行验收 |
| --- | --- | --- |
| 第一阶段：编辑效率 | 框选、复制粘贴/移动/删除、批量操作、填充、重做、落点预览、一键试玩；补齐对称与选区变换、图层 | 连续绘制可一次撤销并重做；矩形选区变换后折纸方向正确；越界粘贴不产生半次写入；四类非法落点均可解释；退出试玩完整恢复编辑状态；刷新恢复已保存设计 |
| 第二阶段：设计验证 | 校验、最短解、路线回放、绕行与机制依赖、可达状态检查 | 已知有解/无解样例结论正确；回放每步与真实试玩一致；可发现普通移动绕行和可跳过轴；预算内外结论区分；改图后旧报告失效 |
| 第三阶段：完整 Demo | 关卡组、参数/备注/快照、分层提示、下一关、试玩记录、完整导入导出 | 教学→练习→挑战三关可连续通关；排序影响推进；复制不共享数据；快照可恢复；关卡组 JSON 往返不丢设计；离线 game.html 完成三关并显示整组完成；无编辑工具或设计备注泄漏 |

每阶段都需要真实浏览器输入与画面验收，桌面和移动视口检查；静态解析和本地求解通过不能替代此项。当前浏览器审批 429 是浏览器验收的外部阻碍，不影响本地设计和规则测试，但未消除前不能宣称视觉验收完成。

## 当前基础与待补齐

已有单关地图编辑、四向折纸、八向移动、通关/步数限制、撤销、连续绘制、本地保存、单关 JSON 和单文件 HTML。新增的大部分选区工具、重做、关卡组、分析 UI、提示与日志仍待实施。

本地 verify-level.cjs 已对当前 Demo 做最短解和轴依赖检查；它不是通用的编辑器内求解功能。升级时应将这些规则验证转为共用求解模块与可交互报告。
